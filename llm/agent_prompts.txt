WIDTH_DSL_PROMPT = """
        任务：将使用者输入的道路宽度修改自然语言，转换为符合 DSL 定义的 JSON。

        输入中会包含两类信息：

        1. 用户指令 user_instruction
        表示用户希望如何修改道路宽度。

        2. 当前选中道路数据 road_data
        格式示例：

        {
            "road_id": "road_12",
            "lane_ids": [3, 2, 1, -1, -2],
            "lane_avg_width": {
                "3": 2.5,
                "2": 2.5,
                "1": 2.5,
                "-1": 3.2,
                "-2": 3.0
            }
        }

        

        road_data 含义：
        - road_id 表示当前选中道路 id，是宽度修改 DSL 中 road_id 字段的必要来源之一。
        - lane_ids 表示当前选中道路包含的车道 id。
        - lane_ids 的顺序表示车道从左到右的排列。
        - lane_avg_width 表示每条车道当前的平均宽度，单位默认为米。
        - 如果用户说“这条路”“当前道路”“选中的道路”，使用 road_data.road_id。
        - 如果 user_instruction 和 road_data 都无法提供可确定的道路 id，不要编造 id，输出 {"operations": []}。
        - 如果用户说“最左侧车道”，对应 lane_ids 中第一个 id。
        - 如果用户说“最右侧车道”，对应 lane_ids 中最后一个 id。
        - 如果用户说“从左数第 N 条车道”，对应 lane_ids 中第 N 个 id。
        - 如果用户说“从右数第 N 条车道”，对应 lane_ids 反向计数的第 N 个 id。
        - 如果用户说“中间车道”，当 lane_ids 数量为奇数时，对应中间位置的车道 id；当 lane_ids 数量为偶数时，该表达存在歧义，不要自行猜测，输出 {"operations": []}。
        - 如果用户说“左侧第 N 条车道”，对应 lane_ids 中从大到小第 N 个正数 id。
        - 如果用户说“右侧第 N 条车道”，对应 lane_ids 中从小到大第 N 个负数 id。
        - 输出到 DSL 的 lane_ids 必须是字符串数组。车道 id 3 输出为 ["lane_3"]，车道 id -1 输出为 ["lane_-1"]。

        只处理宽度修改任务，即 operation 必须为 "width"。
        如果输入包含坡度或弯道修改，不要转换成 width operation。
        最终输出必须是严格 JSON，不要输出解释、Markdown、注释或多余文本。

        顶层结构固定为：

        {
        "operations": [
            {
            "operation": "width",
            "road_id": "string",
            "lane_ids": "string[] | none",
            "road_limit": "number | none",
            "change": {
                "mode": "absolute | relative | none",
                "action": "increase | decrease | set | none",
                "magnitude": {
                "kind": "numeric | qualitative | none",
                "value": "number | none",
                "level": "slight | default | significant | none",
                "unit": "m | percent | none"
                }
            }
            }
        ]
        }

        解析规则：

        1. operation
        - 固定输出 "width"。

        2. road_id
        - road_id 是必填字段，必须来自 user_instruction 中明确指定的道路 id、road_data.road_id，或“所有道路/全部道路/全局修改”等表达。
        - 如果用户指令指定单条道路，例如 road_12，输出 "road_12"。
        - 如果用户指令只说“这条路”“当前道路”“选中的道路”，输出 road_data.road_id。
        - 如果无法确定 id，不要编造，不要输出 "current"，输出 {"operations": []}。

        3. lane_ids
        - 如果用户指令指定具体车道，结合 road_data.lane_ids 解析目标车道。
        - “最左侧车道”对应 lane_ids 第一个 id。
        - “最右侧车道”对应 lane_ids 最后一个 id。
        - “从左数第 N 条车道”对应 lane_ids 第 N 个 id。
        - “从右数第 N 条车道”对应 lane_ids 倒数第 N 个 id。
        - “第 N 条车道”如果未说明从左还是从右，默认按 lane_ids 从左到右解释。
        - 如果用户指令直接指定 lane_2，则输出 ["lane_2"]。
        - 如果用户指令直接指定车道 id 为 2，则输出 ["lane_2"]。
        - 如果用户指令没有限定具体车道，lane_ids 输出 "none"
        - 如果用户要求对某条道路的全部车道进行修改时，输出所有车道，表示该操作作用于整条道路所有车道，车道编号按照 road_data.lane_ids 的原始顺序转换
        - 如果车道位置表达无法根据 road_data.lane_ids 唯一确定，输出 {"operations": []}。

        4. road_limit
        - road_limit 表示最多允许受影响的道路数量，包含初始目标道路本身。
        - 如果用户指令表达“只改当前道路”“仅限这条道路”“不要影响相邻道路”，输出 1。
        - 如果用户指令表达“后面的路也跟着变”“相邻道路也跟着变”，但未指定数量，输出 2。
        - 如果用户指令表达“最多影响 N 条道路”，输出数字 N。
        - 如果用户指令没有传播范围限制，输出 "none"，表示不额外限制传播范围，使用系统默认传播机制。

        5. change.action
        - “加宽”“变宽”“增加宽度”解析为 "increase"。
        - “变窄”“缩窄”“减少宽度”解析为 "decrease"。
        - “改成”“设为”“调整到”“变为某个目标宽度”解析为 "set"。
        - 没有明确动作或不做宽度变化时输出 "none"；此时 mode、magnitude.kind、magnitude.value、magnitude.level、magnitude.unit 都输出 "none"。

        6. change.mode
        - “改成 3.5 米”“设为 4m”表示目标绝对宽度，mode 输出 "absolute"，action 输出 "set"。
        - “加宽 0.5 米”“减少 0.3m”表示绝对变化量，mode 输出 "relative"。
        - “加宽 20%”“缩窄 10%”表示相对当前宽度变化，mode 输出 "relative"。
        - “稍微宽一点”“明显窄一点”属于定性相对变化，mode 输出 "relative"。
        - mode 与 action 必须同为 "none" 或同为非 "none"，不存在一个为 "none" 而另一个有值的情况。
        - relative 表示在当前道路宽度基础上进行修改，absolute 表示直接设置为目标宽度。
        - 如果用户指令基于当前车道平均宽度计算目标值，例如“把最右侧车道加宽到和最宽车道一样”，应使用 road_data.lane_avg_width 计算目标宽度，并输出 mode = "absolute", action = "set"。

        7. change.magnitude.kind
        - 有明确数字或可以根据 road_data 计算出明确数字时，kind 输出 "numeric"。
        - 只有程度词时，kind 输出 "qualitative"。
        - 当 action = "none" 时，kind 输出 "none"。
        - 没有明确幅度时，kind 默认输出 "qualitative"。

        8. change.magnitude.value
        - kind 为 "numeric" 时，输出数字，不要加单位。
        - kind 不是 "numeric" 时，输出 "none"。
        - 如果需要根据 road_data 计算宽度，value 输出计算后的数值。
        - 例如当前 lane_-2 宽度为 3.0 米，用户说“把最右侧车道加宽 0.5 米”，如果 DSL 表达的是变化量，则 value 输出 0.5。
        - 例如当前 lane_-2 宽度为 3.0 米，用户说“把最右侧车道改成 3.5 米”，value 输出 3.5。

        9. change.magnitude.level
        - “稍微”“略微”“一点”输出 "slight"。
        - “一些”“适当”“正常调整”输出 "default"。
        - “大幅”“明显”“显著”输出 "significant"。
        - kind 不是 "qualitative" 时，输出 "none"。
        - 如果 kind = "qualitative" 但用户指令中没有任何程度词，level 输出 "default"

        10. change.magnitude.unit
        - 米、m 输出 "m"。
        - 百分比、% 输出 "percent"。
        - 定性相对修改，例如“稍微变宽”“明显变窄”，输出 "none"。
        - 当"kind" = "qualitative" 时，输出 "none"。
        - 没有幅度或单位时输出 "none"。

        11. 多操作拆分
        - 如果一句话包含多个独立宽度修改任务，必须拆成多个 width operation。
        - 如果一句话同时修改不同车道，且每条车道的修改幅度不同，拆成多个 operation。
        - 如果一句话同时修改多条车道，且修改方式完全相同，必须放在同一个 operation 的 lane_ids 数组中。
        - 如果包含坡度或弯道修改，不要转换成 width operation。

        12. 歧义处理
        - 如果缺少目标车道但用户明确是在改整条路宽度，lane_ids 输出 "none"。
        - 如果缺少可确定道路 id，输出 {"operations": []}。
        - 如果车道位置表达无法根据 road_data 唯一确定，输出 {"operations": []}。
        - 如果用户指令不是宽度修改任务，输出 {"operations": []}。

        - 如果用户说“明显变缓”“大幅变陡”，使用 qualitative + significant。
        - 如果用户同时表达“坡度设为 5%”和“终点抬高 4 米”，这是两个不同 attribute，应拆成两个 operation。
        - 如果用户说“上坡 5%”，解析为 position = "end"，attribute = "grade", mode = "absolute", action = "set", value = -5, unit = "percent"。
        - 如果用户说“下坡 5%”，仍解析为 position = "end"，attribute = "grade", mode = "absolute", action = "set", value = 5, unit = "percent"，不要自行添加负号，要根据修改位置最终确定。
        - 如果用户明确写出“将道路终点的坡度修改为-5%”，attribute = "grade", mode = "absolute", action = "set", value = -5, unit = "percent"。用户为提及是上坡还是下坡，因此直接按照用户的描述解释

        14. 一致性约束
        - kind = "numeric" 时，value 必须是 number，level 必须是 "none"，unit 不能是 "none"。
        - kind = "qualitative" 时，value 必须是 "none"，level 必须是 "slight"、"default" 或 "significant"，unit 必须是 "none"。
        - kind = "none" 时，value、level、unit 都必须是 "none"。
        - action = "increase" 或 "decrease" 时，mode 必须是 "relative"。
        - action = "none" 时，attribute 和 mode 必须为 "none"。
        - attribute = "none" 时，action、mode、kind、value、level、unit 都必须为 "none"。
        - JSON 中不要使用 null。
        - 未指定字段使用字符串 "none"。
        - 所有 operation 必须字段完整。
        - 不要输出 DSL 中未定义的字段。

            计算不对称程度：
            |p_s - p_e|

            ## 1. 修正方向与对象
            对称性修正只允许修改一个 modification，另一个 modification 保持完整默认 none 结构。

            ### 情形 A：p_s < p_e
            表示左短右长，重心偏左。
            为了让两侧更对称，只调整 modification[0]，使其向右移动：
            modification[0].centroid_shift.change.action = "move_to_end"

            同时：
            - modification[1].centroid_shift 输出完整默认 none 结构。
            - 不得同时移动 modification[0] 和 modification[1]。

            ### 情形 B：p_s > p_e

            表示左长右短，重心偏右。
            为了让两侧更对称，只调整 modification[1]，使其向左移动：
            modification[1].centroid_shift.change.action = "move_to_start"
            同时：
            - modification[0].centroid_shift 输出完整默认 none 结构。
            - 不得同时移动 modification[0] 和 modification[1]。

            ### 情形 C：|p_s - p_e| < 0.1

            表示道路已经基本对称，不进行位置调整。
            - modification[0].centroid_shift 输出完整默认 none 结构。
            - modification[1].centroid_shift 输出完整默认 none 结构。
            - 如果用户未表达弯曲强度变化，两个 modification 的 curvature_peak 也输出完整默认 none 结构。

            ## 2. 幅度选择

            根据 |p_s - p_e| 选择 qualitative level：
            - 0 ≤ |p_s - p_e| < 0.25："slight"
            - 0.25 ≤ |p_s - p_e| ≤ 0.40："default"
            - |p_s - p_e| > 0.40："significant"

            ## 3. magnitude 设置

            对称性修正采用定性、相对调整：

            - centroid_shift.change.mode = "relative"
            - centroid_shift.change.magnitude.kind = "qualitative"
            - centroid_shift.change.magnitude.value = "none"
            - centroid_shift.change.magnitude.level 根据 |p_s - p_e| 选择
            - centroid_shift.change.magnitude.unit = "none"

            ## 4. 核心约束

            - 每次对称性修正只修改一个 modification。
            - p_s < p_e、重心偏左时，只修改 modification[0]，方向为 move_to_end。
            - p_s > p_e、重心偏右时，只修改 modification[1]，方向为 move_to_start。
            - 未被修改的 modification 必须输出完整默认 none 结构。
            - 不得同时移动两个 modification。
            - 幅度始终按照 |p_s - p_e| 计算，不额外放大。


            ---

            # 自然语言到 modification 的判断优先级：

            1. 如果用户明确描述“入弯 / 前半段 / 起点侧 / 起点这边 / 左边”，只修改 modification[0]。
            2. 如果用户明确描述“出弯 / 后半段 / 终点侧 / 终点这边 / 右边”，只修改 modification[1]。
            3. 如果用户描述“整体弯道 / 整个弯 / 整段弯道 / 弯道位置”，同时修改 modification[0] 和 modification[1]。
            4. 如果用户描述“弯道提前 / 早点转 / 整体往左”，两个 modification 都按 left 方向移动，即 action = "move_to_start"。
            5. 如果用户描述“弯道推后 / 晚点转 / 整体往右”，两个 modification 都按 right 方向移动，即 action = "move_to_end"。
            6. 如果用户描述“对称 / 匀称 / 两边一样”，根据 road_data.p_s 和 road_data.p_e 的差值执行对称性逻辑。
            7. 如果用户只描述 shape 或 semantic，不修改 modification 的曲率强度或质心偏移。
            8. 如果用户表达模糊，例如“调整一下这个弯”，但没有说明更急、更缓、前段、后段、整体、形态、语义、位置、开口或对称性，输出：

            {
            "operations": []
            }

            ---

            # road_limit 说明：
            - 如果用户指令表达"只改当前道路""仅限这条道路""不要影响相邻道路"，输出 1。
            - 如果用户指令表达"后面的路也跟着变"但未指定数量，输出 2。
            - 如果用户指令没有传播范围限制，输出 "none"。

        - 检查是否多出了用户没有要求的修改.
        - 检查是否将参数不同的修改错误合并.
        - 检查是否对同一目标输出了重复或互相冲突的操作.

        --------------------------------------------------
        5. 空 operations 检查
        --------------------------------------------------

        以下情况预期应为:

        {
        "operations": []
        }

        - 用户指令不是宽度修改.
        - 无法确定道路 id.
        - 目标车道存在无法消除的歧义.
        - 车道位置超出 road_data.lane_ids 范围.
        - 用户只要求坡度、弯道或其他非宽度修改.

        如果预期为空数组但 DSL 生成了 operation,需要说明为什么该 operation 不应该存在.

        如果预期存在宽度修改但 DSL 返回空数组,需要说明缺少了什么修改.
        
        --------------------------------------------------
        6. 问题来源判断
        --------------------------------------------------

        如果检查发现问题,需要进一步判断问题来源.

        问题来源分为以下四种:

        1. none

        表示没有发现问题.

        适用情况:

        - dsl_output 结构正确；
        - user_instruction 能够形成明确、可执行的宽度修改要求；
        - DSL 表达的完整修改语义与用户要求一致.

        2. extraction_error

        表示 user_instruction 本身明确且可以执行,但 DSL 在提取或转换过程中出现错误.

        包括但不限于:

        - dsl_output 不是合法 JSON；
        - DSL 缺少字段、字段类型错误或使用了非法值；
        - 提取了错误的道路或车道；
        - 遗漏了用户要求的修改；
        - 增加了用户没有要求的修改；
        - action、mode、value、unit 等参数组合表达了错误的修改含义；
        - 将不同的修改错误合并；
        - 对同一个目标生成重复或冲突的操作.

        3. user_requirement_error

        表示问题来自 user_instruction 本身,用户要求无法形成明确、唯一、可执行的宽度修改.

        包括但不限于:

        - 无法确定目标道路；
        - 目标车道描述存在无法消除的歧义；
        - 车道位置超出 road_data.lane_ids 的范围；
        - 用户要求前后矛盾；
        - 缺少完成修改所必需的目标信息；
        - 用户要求的内容不属于道路宽度修改任务.

        如果用户要求存在上述问题,而 DSL 正确返回:

        {
        "operations": []
        }

        则不属于提取错误,但整体检查仍不通过,问题来源应为 "user_requirement_error".

        4. both

        表示用户要求本身存在问题,同时 DSL 也存在独立的提取错误.

        例如:

        - 用户没有提供可确定的目标道路,但 DSL 仍然编造了 road_id；
        - 用户对目标车道的描述存在歧义,但 DSL 自行猜测并生成了具体车道；
        - 用户要求不属于宽度修改任务,但 DSL 仍然生成了 width operation；
        - 用户要求存在冲突,并且 dsl_output 本身还存在字段结构错误.

        判断要求:

        - DSL 的结构问题都属于提取过程中的错误.
        - 用户要求明确,但 DSL 与用户要求不一致时,属于 "extraction_error".
        - 用户要求无法明确执行,并且 DSL 正确拒绝生成操作时,属于 "user_requirement_error".
        - 用户要求无法明确执行,但 DSL 仍然猜测或生成错误操作时,属于 "both".
        - 不能因为 DSL 返回空 operations,就直接判断没有问题,必须先判断用户要求是否明确且可执行.

        ==================================================
        三、输出格式
        ==================================================

        最终只输出一个 JSON 对象,固定包含以下三个字段:

        {
        "passed": true,
        "problem_source": "none",
        "check_result": "OK"
        }

        字段说明:

        1. passed

        - 没有任何结构问题、语义问题或用户要求问题时输出 true.
        - 存在任意问题时输出 false.
        - passed 为 true 时,problem_source 必须为 "none".
        - passed 为 false 时,problem_source 不能为 "none".

        2. problem_source

        只能使用以下值:

        - "none":没有问题.
        - "extraction_error":问题来自 DSL 的提取或转换过程.
        - "user_requirement_error":问题来自用户要求本身.
        - "both":用户要求和 DSL 提取过程都存在问题.

        3. check_result

        如果没有问题,固定输出:
        "OK"

        如果存在问题,使用一个字符串描述结构问题、语义问题以及用户要求问题,格式为:
        "结构问题:具体问题描述；语义问题:具体问题描述；用户要求问题:具体问题描述"

        要求:

        - 如果结构没有问题,输出"结构问题:无".
        - 如果语义没有问题,输出"语义问题:无".
        - 如果用户要求没有问题,输出"用户要求问题:无".
        - 如果 dsl_output 无法解析,说明具体结构问题,并输出"语义问题:DSL 无法解析,未进行语义检查".
        - 如果有多个问题,应在对应部分中依次说明.
        - 问题描述应指出当前 DSL 实际表达了什么,以及它与用户要求有什么差异.
        - 不要只写"字段错误""参数错误"或"语义不一致"等笼统结论.
        - 不要输出修改后的完整 DSL.
        - 不要输出分析过程.
        - 不要增加其他字段.

        ### action = "increase" 或 "decrease" 时

        - value 必须大于 0。
        - value = 0 不表示实际增加或减少，应判定为字段组合错误。
        - value < 0 与 increase、decrease 的动作方向冲突，应判定为字段组合错误。
        - 对 grade 的相对增加或减少：

        - unit = percent 时，value 表示坡度大小的正比例变化量。
        - unit = degree 时，value 表示坡角大小的正变化量。
        - 对 elevation_delta 的相对增加或减少：

        - unit = m 时，value 表示正的高程变化量。
        - unit = percent 时，value 表示正的百分比变化量。

        ### grade + absolute + set 时

        - unit = percent 时，value 可以为正数、负数或 0。
        - 正数表示上坡，负数表示下坡，0 表示平路。
        - unit = degree 时，value 必须满足 -90 < value < 90。
        - 正负号和 0 的方向含义与坡度百分比相同。
        - 完整方向换算规则以“六、坡度方向和数值正负”为准。

        ### grade + relative + set + percent 时

        - value 必须大于等于 0。
        - value 表示最终坡度大小占当前坡度大小的比例。
        - value = 0 表示将最终坡度大小设置为当前坡度大小的 0%，即变为平路。
        - value < 0 会产生未定义的方向反转语义，应判定为字段组合错误。
        - grade + relative + set + degree 仍属于无法形成明确语义的非法组合。

        ### elevation_delta + absolute + set + m 时

        - value 可以为正数、负数或 0。
        - value 表示端点最终绝对高程。
        - 负数可以表示低于高程基准面的绝对高程，不得仅因数值为负判定非法。

        ### elevation_delta + relative + set + percent 时

        - value 必须大于等于 0。
        - value 表示端点最终高程为该端点当前高程的指定比例。
        - value = 0 表示将端点最终高程设置为当前高程的 0%。
        - value < 0 不符合当前高程比例设置规则，应判定为字段组合错误。


        ## 5. JSON 无法解析时

        如果 dsl_output 无法解析为严格 JSON：

        - passed 必须为 false。
        - problem_source 必须包含 DSL 提取错误，即为 "extraction_error" 或 "both"。
        - check_result 中必须说明具体结构问题。
        - 不再进行完整 DSL 反向语义检查。
        - 仍然可以判断 user_instruction 是否本身存在明显冲突或缺失。
        - 语义部分输出：
        “语义问题：DSL 无法解析，未进行反向语义检查”。

        ==================================================
        # 二、整体语义一致性检查
        ==================================================

        语义检查必须分三步完成。

        ## 第一步：
            理解用户要求。根据 user_instruction、road_data 和默认规则，推导用户要求中的完整修改，包括目标道路、位置、传播范围、修改属性、动作、模式、数值含义、单位、定性程度、操作数量和操作顺序。不能为了匹配当前 DSL 而改变对用户原始要求的理解。

        ## 第二步：
            反向解释 DSL。只能根据 dsl_output 当前字段及 DSL 定义解释每个 operation 实际表达的完整道路修改，不能根据 user_instruction 猜测 DSL “本来想表达什么”。必须把 road_id、position、road_limit、attribute、mode、action、magnitude 组合起来解释，并说明数值是最终目标值、相对变化量还是当前值比例。

        ## 第三步：比较完整语义和修改目的
            首先比较目标道路、修改位置、传播范围、修改属性、模式、动作、数值类型、数值大小、程度、单位、坡度方向、操作数量、操作顺序和最终执行效果，判断 DSL 是否保持用户要求的完整动作语义。
            - 如果完整动作语义一致，该语义检查通过。
            - 如果完整动作语义不一致，必须继续判断当前 DSL 是否仍能完整满足用户的修改目的。
            - 如果 DSL 在当前 `road_data` 和既定执行规则下能够确定地达到用户要求的最终修改效果，且不存在遗漏、增加、重复、冲突、错误传播、错误位置或顺序副作用，该语义检查仍可通过。
            - 如果完整动作语义和修改目的均不满足，语义检查不通过。
            - 两项中任意一项通过即可；不能在第一项不通过后直接结束检查。

        ### 手段与目的表达规则
        当用户指令同时包含“直接修改手段”和“预期目的”时，应优先按照直接修改对象确定 DSL 属性，目的部分只作为结果约束，不要求生成额外 operation。
        例如“降低终点以适度减小坡度”中：

        - “降低终点”是直接修改手段，应使用 OKattribute = elevation_deltaOK、OKposition = endOK、OKaction = decreaseOK；
        - “适度减小坡度”是预期目的，不要求改用 OKattribute = gradeOK，也不要求额外生成 grade operation；
        - “适度”可以由该 elevation_delta operation 的 OKmagnitude.level = defaultOK 表达。

        判断目的是否满足时，应结合 OKroad_dataOK 判断端点移动方向：
        - 当 OKend_elevation > start_elevationOK 时，降低终点会减小两端高程差，因此满足减小坡度的目的；
        - 当 OKend_elevation < start_elevationOK 时，降低终点会增大两端高程差，因此不满足减小坡度的目的。

        对于 qualitative 修改，只需确认修改方向、程度等级和因果方向一致，不得因为缺少具体降低米数或道路长度，就判定无法保证坡度减小程度。


        ==================================================
        # 三、多字段组合含义解释
        ==================================================

        不能将 DSL 字段孤立翻译，也不能只检查单个字段是否与用户指令中的某个词对应。

        ### 必须先回答：
        “当前 DSL 的所有字段组合起来，实际会对哪条道路的哪个位置执行什么修改？”

        ### 然后再回答：
        “这个完整操作是否与用户要求一致？”

        ### 检查结果不能只写：
        - position 错误；
        - mode 错误；
        - action 错误；
        - value 错误；
        - unit 错误；
        - 参数不一致；
        - 语义错误。

        ### 必须说明：
        1. 当前 DSL 的完整字段组合实际表达什么；
        2. 用户要求的完整语义是什么；
        3. 两者具体有什么差异。

        ## 组合一：绝对设置坡度或坡角

        ### DSL：

        坡度百分比：
                {
                "position": "end",
                "change": {
                    "attribute": "grade",
                    "mode": "absolute",
                    "action": "set",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 5,
                        "level": "none",
                        "unit": "percent"
                    }
                }
                }

        坡角：

                {
                "position": "end",
                "change": {
                    "attribute": "grade",
                    "mode": "absolute",
                    "action": "set",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 3,
                        "level": "none",
                        "unit": "degree"
                    }
                }
                }

        ### 完整含义

        - unit = percent：通过调整 position 指定的受控端，将道路最终坡度设置为 value 对应的百分比。
        - unit = degree：通过调整 position 指定的受控端，将道路最终坡角设置为 value 对应的角度。
       

        例如：

        - position = start、value = 5、unit = percent：从 start 到 end 上坡 5%。
        - position = start、value = -5、unit = percent：从 start 到 end 下坡 5%。
        - position = end、value = 5、unit = percent：从 end 到 start 上坡 5%，等价于从 start 到 end 下坡 5%。
        - position = end、value = -5、unit = percent：从 end 到 start 下坡 5%，等价于从 start 到 end 上坡 5%。


        ### 核心规则

        - 本组合的坡度正负方向统一遵循“六、坡度方向和数值正负”中的权威定义。
        - position 指定受控端点，同时指定 value 正负号的方向起点。
        - value 表示最终目标坡度或坡角，不表示相对变化量。
        - position 同时表示坡度修改的受控端点和坡度正负方向的出发端点。
        - 相同的非零 value 在 position = start 和 position = end 下，换算到同一固定道路方向时，坡度方向相反。
        - 比较用户要求与 DSL 时，必须先根据 position 和 value 的组合换算出实际物理坡向，不能脱离 position 单独依据数值正负判断上坡或下坡。
        - 该正负方向规则统一适用于 percent 和 degree。
        - position = both 不适用于需要以单个端点作为方向基准的 grade 修改。
        - 设置为 3 度表示从 position 指定端点出发的最终目标坡角为 3 度，不表示设置为 3%、坡角相对增加 3 度或端点抬高 3 米。

        ## 组合二：坡度按百分比相对增加、减少或设置

        ### DSL：
        相对增加：
                {
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 5,
                        "level": "none",
                        "unit": "percent"
                    }
                }
                }

        相对减少：
                {
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "decrease",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 20,
                        "level": "none",
                        "unit": "percent"
                    }
                }
                }

        设置为当前坡度的某个比例：
                {
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "set",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 30,
                        "level": "none",
                        "unit": "percent"
                    }
                }
                }

        ### 完整含义：
        - relative + increase + 5%：在当前坡度大小的基础上增加 5%。
        - relative + decrease + 20%：在当前坡度大小的基础上减少 20%。
        - relative + set + 30%：将道路最终坡度设置为当前坡度的 30%。

        例如当前坡度大小为 10%：
        - increase 5% 后为 10.5%。
        - decrease 20% 后为 8%。
        - set 30% 后为 3%。

        ### 核心规则：
        - relative + increase：value 表示相对增加比例。
        - relative + decrease：value 表示相对减少比例。
        - relative + set：value 表示最终值占当前坡度的比例。
        - absolute + set：value 表示最终绝对坡度。
        - relative + set + 50% 与 relative + decrease + 50% 的完整动作语义不同：前者表达将最终坡度设置为当前坡度的 50%，后者表达在当前坡度基础上减少 50%。
            - 在第一级完整动作语义检查中，两者不能视为相同动作。
            - 如果第一级检查不通过，必须继续进行修改目的检查。
            - 当 road_data 足以确定两种操作在当前状态下具有完全相同的最终结果，并且目标道路、受控位置、坡度方向、传播范围、操作顺序及其他执行效果也完全一致时，可以判定 DSL 满足用户修改目的。
            - 如果只能证明两种操作在部分情况或特定假设下可能得到相同结果，不能判定修改目的检查通过。

        ## 组合三：坡角的相对修改

        ### DSL：
        相对增加坡角：
                {
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 3,
                        "level": "none",
                        "unit": "degree"
                    }
                }
                }
        相对设置坡角：
                {
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "set",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 3,
                        "level": "none",
                        "unit": "degree"
                    }
                }
                }

        ### 完整含义：
        - relative + increase + 3 degree：在当前坡角大小的基础上增加 3 度。
        - relative + set + 3 degree：现有规则无法形成明确的相对设置语义。

        ### 核心规则：
        - relative + increase/decrease + degree 中，degree 表示坡角变化量。
        - 相对增减坡角时，默认保持当前上坡或下坡方向。
        - relative + set + percent 表示设置为当前值的某个比例。
        - degree 不是比例单位，因此 relative + set + degree 无法按现有规则形成明确语义。
        - 除非执行层另有明确定义，否则 relative + set + degree 应判定为字段组合语义错误。

        ## 组合四：坡度的定性增加或减少

        ### DSL：
        定性增加：
                {
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "qualitative",
                        "value": "none",
                        "level": "slight",
                        "unit": "none"
                    }
                }
                }
        定性减少：
                {
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "decrease",
                    "magnitude": {
                        "kind": "qualitative",
                        "value": "none",
                        "level": "significant",
                        "unit": "none"
                    }
                }
                }
        ### 完整含义：
        - increase + slight：稍微增大道路坡度，使道路稍微变陡。
        - decrease + significant：明显减小道路坡度，使道路明显变缓。

        ### 核心规则：
        - increase 表示变陡，decrease 表示变缓。
        - slight：稍微、略微、一点、小幅。
        - default：普通程度、适当、一些或未明确程度。
        - significant：明显、大幅、显著、很多。
        - qualitative magnitude 仍然表示实际修改，不能因为没有 numeric value 就判定 operation 无效。
        - 不需要恢复用户原始措辞，只比较程度语义。

        ## 组合五：单个端点的数值高程修改

        ### DSL：
        相对抬高端点：
                {
                "position": "end",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 4,
                        "level": "none",
                        "unit": "m"
                    }
                }
                }
        相对降低端点：
                {
                "position": "start",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "relative",
                    "action": "decrease",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 4,
                        "level": "none",
                        "unit": "m"
                    }
                }
                }
        按百分比相对抬高或降低端点：
                {
                "position": "end",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 20,
                        "level": "none",
                        "unit": "percent"
                    }
                }
                }
        设置端点绝对高程：
                {
                "position": "end",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "absolute",
                    "action": "set",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 4,
                        "level": "none",
                        "unit": "m"
                    }
                }
                }
        设置为端点当前高程的某个比例：
                {
                "position": "start",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "relative",
                    "action": "set",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 30,
                        "level": "none",
                        "unit": "percent"
                    }
                }
                }

        ### 完整含义：
        - relative + increase + 4m：将指定端点在当前高程基础上抬高 4 米。
        - relative + decrease + 4m：将指定端点在当前高程基础上降低 4 米。
        - relative + increase/decrease + 20%：将指定端点高程相对增加或减少 20%。
        - absolute + set + 4m：将指定端点的最终高程设置为 4 米。
        - relative + set + 30%：将指定端点的目标高程设置为该端点当前高程的 30%。

        ### 核心规则：
        - position = start：只修改起点。
        - position = end：只修改终点。
        - relative + increase/decrease + m 中，value 表示高程变化量。
        - relative + increase/decrease + percent 表示对指定端点高程进行百分比相对增减。
        - 检查时只判断字段类型、枚举值和组合是否合法，不检查百分比计算基数、零高程、负高程实际运算方式。
        - absolute + set + m 中，value 表示修改后的目标高程。
        - relative + set + percent 表示将指定端点的最终高程设置为该端点当前高程的某个比例，percent 的计算基数是该端点的当前高程。
        - absolute + set 只用于直接设置不依赖当前高程的绝对目标值，因此在 elevation_delta 中应与 unit = m 组合。
        - elevation_delta + absolute + set + percent 属于模式与数值含义不一致的非法组合。
        - 设置为当前高程的 30% 不表示将端点抬高 30%。
        - 必须结合 position 判断最终执行效果。

        ## 组合六：整条道路或两个端点的高程修改

        整条道路整体抬高：

                "position": "both",

                    "attribute": "elevation_delta",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 2,
                        "level": "none",
                        "unit": "m"
                    }
                }
                }
        整条道路整体降低：
                {
                "position": "both",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "relative",
                    "action": "decrease",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 2,
                        "level": "none",
                        "unit": "m"
                    }
                }
                }
        将两个端点设置为同一绝对高程：
                {
                "position": "both",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "absolute",
                    "action": "set",
                    "magnitude": {
                        "kind": "numeric",
                        "value": 10,
                        "level": "none",
                        "unit": "m"
                    }
                }
                }

        ### 完整含义：
        - both + relative + increase + 2m：将起点和终点同时抬高 2 米。
        - both + relative + decrease + 2m：将起点和终点同时降低 2 米。
        - both + absolute + set + 10m：将起点和终点的最终高程都设置为 10 米。

        ### 核心规则：
        - both + relative + increase/decrease 表示两个端点等量升降。
        - 两端等量升降时，起终点高程差保持不变，道路坡度通常保持不变，道路发生整体高程平移。
        - both + absolute + set 表示将两个端点分别设置为同一目标高程。
        - 两端设置为同一目标高程后，道路通常变为平路。
        - both + absolute + set 不等于整条道路整体抬高或降低。

        ## 组合七：高程的定性增加或减少

        ### DSL：
                {
                "position": "end",
                "change": {
                    "attribute": "elevation_delta",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "qualitative",
                        "value": "none",
                        "level": "slight",
                        "unit": "none"
                    }
                }
                }

        ### 完整含义：
        “将道路终点稍微抬高。”

        同类组合中：
        - increase 表示提升水平高度。
        - decrease 表示降低水平高度。
        - position = both 表示两个端点按同等程度整体升降。

        ### 核心规则：
        - qualitative magnitude 可以表示非数值的高程升降。
        - action 决定抬高或降低。
        - level 表示修改程度。
        - position 决定修改起点、终点或两个端点。

        ## 组合八：道路传播范围

        ### DSL：

        只作用于当前道路：
                {
                "road_id": "road_8",
                "road_limit": 1
                }
        最多作用于两条道路：
                {
                "road_id": "road_8",
                "road_limit": 2
                }
        未表达明确数量限制：
                {
                "road_id": "road_8",
                "road_limit": "none"
                }

        ### 完整含义：
        - road_limit = 1：只作用于初始目标道路 road_8，不传播到其他道路。
        - road_limit = 2：最多作用于两条道路，数量包含初始目标道路 road_8。位置语义
        - road_limit = "none"：用户没有表达明确的道路数量限制。

        ### 核心规则：
        - road_limit = N 表示最多作用于 N 条道路。
        - N 包含初始目标道路本身。
        - road_limit = 2 不表示在初始道路之外再影响两条道路。
        - road_limit = "none" 不能自动解释为只修改当前道路或允许影响所有道路。
        - 用户未提出传播范围时，默认 road_limit = "none"。

        ## 组合九：字段组合无法形成唯一执行语义

        ### DSL：
        position = both 与 grade：
                {
                "position": "both",
                "change": {
                    "attribute": "grade",
                    "mode": "relative",
                    "action": "increase",
                    "magnitude": {
                        "kind": "qualitative",
                        "value": "none",
                        "level": "significant",
                        "unit": "none"
                    }
                }
                }

        ### 完整含义：
        position = both + grade：现有字段没有说明两个端点应分别如何移动，无法形成唯一的坡度修改语义。

        ### 核心规则：
        - grade 修改通常需要确定一个受控端。
        - position = both 不能说明两个端点应如何分别移动以改变坡度。
        - 除非执行层明确补充 position = both 对 grade 的执行规则，否则该组合应判定为字段组合语义错误。

        ## 组合十：完整 none 结构

        ### DSL：
                {
                "change": {
                    "attribute": "none",
                    "mode": "none",
                    "action": "none",
                    "magnitude": {
                        "kind": "none",
                        "value": "none",
                        "level": "none",
                        "unit": "none"
                    }
                }
                }

        ### 完整含义：
        “该 operation 没有表达任何实际的坡度或高程修改。”

        ### 核心规则：
        - 用户没有 slope 修改要求时，通常应返回空 operations。
        - 用户存在明确 slope 修改要求时，该结构表示遗漏用户要求。
        - none 结构不能和任何有效属性、动作、数值或单位混用。

        ==================================================
        # 四、道路目标语义
        ==================================================

        - 用户明确指定 road_21、21号道路、道路21 时，目标道路应为 "road_21"，且优先于 road_data.road_id。
        - 用户说“当前道路”“这条路”“选中的道路”“当前选中路段”“该道路”时，使用 road_data.road_id。
        - 本提示词采用默认目标规则：当 user_instruction 未指定其他道路，且 road_data 提供 road_id 时，默认目标为当前选中道路 road_data.road_id。
        - 如果 user_instruction 没有指定道路、road_data 没有 road_id、也没有其他上下文能够确定目标道路，则用户要求无法形成唯一可执行操作，预期应为 {"operations": []}。
        - 如果无法确定道路但 DSL 自行编造 road_id，problem_source 应为 "both"。
        - 多道路修改必须分别生成 operation，不能合并 road_id、遗漏道路或把一条道路的修改应用到另一条道路。

        ==================================================
        # 五、位置语义
        ==================================================

        position 必须结合用户指定位置、attribute、action 和 road_data 共同解释。

        - 明确指定“起点”“起始端”“入口端”“开始端”“起点侧”时，对应 position = "start"。
        - 明确指定“终点”“结束端”“出口端”“末端”“终点侧”时，对应 position = "end"。
        - “整条路抬高 1 米”“当前道路整体降低 2 米”“全段一起升高”“起点和终点同时抬高相同数值”“整条道路平移到更高位置”对应 position = "both"，通常应为 elevation_delta + relative + increase/decrease。
        ### grade 修改的 position 判定顺序

        对于 attribute = "grade" 的 operation，必须先确定 position，再确定绝对坡度或坡角的 value 正负号。

        按以下优先级确定 position：
        1. 用户明确指定受控端点时：
            - 明确指定起点、入口端、开始端等，使用 position = "start"；
            - 明确指定终点、出口端、结束端等，使用 position = "end"。
            - 用户明确指定的受控端点优先于所有默认规则。
        2. 用户没有指定受控端点时，position的选取规则如下：
            - end_elevation > start_elevation：默认 position = "end"；
            - start_elevation > end_elevation：默认 position = "start"；
            - start_elevation = end_elevation：默认 position = "end"。
            确定 position 后，grade + absolute + set 的 value 符号按以下规则确定：
            - position = "start"：
                - 从 start 到 end 上坡，value 为正数；
                - 从 start 到 end 下坡，value 为负数。
            - position = "end"：
                - 从 start 到 end 上坡，value 为负数；
                - 从 start 到 end 下坡，value 为正数。
            不得在确定 position 之前，仅根据“上坡”或“下坡”直接确定 value 的正负号。
        - 确定 position 后，再将用户描述的固定道路方向换算为相对于 end 的 value 正负号。
        - 在用户仅描述了“将某点的坡度设置到XX”时，这种情况判断为无明确指定受控端点，仍然需要根据 end_elevation 和 start_elevation 的关系确定 position。
        - attribute = "elevation_delta" 时：明确起点升降为 "start"，明确终点升降为 "end"，明确整体升降为 "both"；如果无法确定起点、终点或整条道路，属于用户要求问题。
        - “整体坡度变陡”“整条路坡度变缓”“全段坡度增加”中的“整体”修饰坡度属性，不表示起点和终点同时等量移动，不能因此直接输出 position = "both"。
        - “起点和终点同时抬高 1 米”可以由一个 position = "both" operation 表达，也可以由 start 和 end 两个完全等价 operation 表达；本检查关注执行语义是否一致。

        ==================================================
        # 六、坡度方向和数值正负
        ==================================================
        ## 0. 规则优先级

        - 本节是 grade + absolute + set 的坡度或坡角方向、value 正负号以及方向换算的唯一权威定义。
        - 其他章节只用于说明数值范围、默认 position 或提供示例。
        - 如果其他章节中的描述与本节冲突，以本节为准。
        - 本节的方向规则统一适用于 unit = "percent" 和 unit = "degree"。
        - 对于 grade + absolute + set，坡度或坡角的正负方向不是固定以 start 到 end 判断，而是以 position 指定端点为出发点判断。
        ## 1. 局部方向定义

        对于 grade + absolute + set：

        - position 指定实际受控端点，同时指定 value 正负号的方向起点。
        - position = "start" 时，局部方向为 start 到 end。
        - position = "end" 时，局部方向为 end 到 start。
        - value > 0 表示从 position 指定端点朝另一端上坡。
        - value < 0 表示从 position 指定端点朝另一端下坡。
        - value = 0 表示平路。
        - position = "both" 无法提供唯一的方向起点，因此不能用于 grade 修改。

        ## 2. 固定道路方向换算

        当用户使用“从起点到终点上坡”“从 start 到 end 下坡”等固定道路方向描述时，必须将 DSL 的局部方向换算为 start 到 end 的固定方向：

        - position = "start"：
            - start 到 end 的有符号坡度值 = value。
        - position = "end"：
            - start 到 end 的有符号坡度值 = -value。

        因此：

        - position = "start"、value > 0：从 start 到 end 上坡；
        - position = "start"、value < 0：从 start 到 end 下坡；
        - position = "end"、value > 0：从 start 到 end 下坡；
        - position = "end"、value < 0：从 start 到 end 上坡。

        不能脱离 position，仅根据 value 的正负号判断固定道路方向。

        ## 3. 用户未明确方向时

        - 当 user_instruction 只表达“将坡度或坡角设置为某个数值”，但没有出现“上坡”“下坡”“正坡”“负坡”“从 start 到 end”“从 end 到 start”“保持原坡向”“方向不变”“反转坡向”等方向要求时，用户只约束最终坡度或坡角的大小，不约束最终坡向。
        - 此时不得根据 start_elevation、end_elevation 或 grade_degree 推导“用户要求保持道路原始坡向”。
        - 此时不得仅因 DSL 执行后坡向与原始道路不同，就判定 DSL 与用户要求语义不一致。
        - 对 grade + absolute + set + numeric，应将 DSL 换算到统一道路方向后，比较其绝对值与用户要求的数值大小；绝对值一致即可视为数值要求一致。
        - 只有用户明确表达了坡向，或者明确要求保持、改变、反转当前坡向时，坡度方向和 value 正负号才属于必须匹配的用户要求。
        - 用户明确表达方向时，仍按照本节前述固定道路方向换算规则严格检查。
        ==================================================
        # 七、传播范围语义
        ==================================================

        - “只改当前道路”“仅限这条道路”“不要影响相邻道路”对应 road_limit = 1。
        - “相邻道路也跟着变”“后面的路也一起调整”未指定数量时，默认 road_limit = 2。
        - “最多影响 N 条道路”“包括当前道路在内影响 N 条”对应 road_limit = N。
        - road_limit 的数量包含初始目标道路本身。例如 road_limit = 3 表示最多作用于初始目标道路加最多两条传播道路。
        - 用户没有传播范围要求时，road_limit = "none" 可以接受；如果执行系统默认只修改当前道路，road_limit = 1 也可以接受，但检查结果不能声称用户明确要求了某种传播范围。
        - 用户明确“不影响其他道路”但 DSL 使用 "none" 时，需要结合执行层对 "none" 的定义判断是否可能传播。

        ==================================================
        # 八、多操作检查
        ==================================================

        - 不同属性必须拆分。例如“把坡度设为 5%，再把终点抬高 4 米”包含 grade 和 elevation_delta 两个独立修改。
        - 不同道路必须拆分，不能合并 road_id、遗漏道路或错误应用到另一道路。
        - 起点和终点修改方式不同必须拆分；起点和终点完全相同的高程修改可以使用 both，也可以在纯语义检查中接受两个等价 operation。
        - 完全独立的操作可以忽略排列顺序；同一道路、同一属性且包含 relative 修改时，顺序可能影响结果，必须检查顺序。
        - DSL 遗漏用户要求的独立修改、增加用户未要求的修改、重复生成会重复执行的 operation、或生成互相冲突的 operation，均属于 DSL 提取问题。
        - 宽度或弯道修改不能被转换成 slope operation；如果 user_instruction 同时包含 slope 和非 slope 修改，只检查 slope 部分。

        ==================================================
        # 九、空 operations 检查
        ==================================================

        以下情况预期应为 {"operations": []}：
        - 用户指令完全不属于坡度、坡角、高差或高程修改任务；无法确定目标道路；
        - 修改高程但无法确定起点、终点或整条道路；
        - 用户要求内部冲突；缺少执行必要信息；
        - 只要求宽度、弯道、曲率或其他非 slope 修改；坡度方向和数值符号冲突且无法消除；

       
        空 operations 的语义是“DSL 没有表达任何 slope 修改”。不能因为 operations 为空且结构合法就直接判断通过：如果用户存在明确可执行的 slope 修改但 DSL 返回空数组，属于 extraction_error；如果用户要求本身无法执行且 DSL 正确返回空数组，整体仍不通过，problem_source 为 user_requirement_error；如果用户要求无法执行但 DSL 仍自行生成 operation，problem_source 为 both。

        当 user_instruction 完全不属于坡度、坡角、高差或高程修改任务时，正确的 DSL 应返回 {"operations": []}。空数组表示 DSL 没有错误生成 slope 操作，但由于用户要求不属于本任务支持范围，整体检查仍然不能通过：

        - passed 必须为 false；
        - problem_source 必须为 "user_requirement_error"；
        - check_result 的结构问题和语义问题可以为“无”，用户要求问题必须说明该要求不属于 slope 修改任务。

        不得因为 DSL 正确返回空 operations 而将该类输入判定为通过。
        ==================================================
        # 十、非 slope 任务检查
        ==================================================

        坡度、坡角、上坡、下坡、变陡、变缓、高差、起点高程、终点高程、抬高、降低和道路整体升降属于 slope 相关任务。道路宽度、车道数量、弯道、曲率、转弯半径、道路材质和道路颜色通常不属于 slope 任务。

        如果 user_instruction 完全不包含 slope 修改要求：

        - 预期 DSL 为 {"operations": []}；
        - DSL 不得将宽度、弯道、曲率、材质、颜色等非 slope 修改转换为 slope operation；
        - 即使 DSL 正确返回空 operations，整体检查仍必须判定为不通过；
        - passed 必须为 false；
        - problem_source 必须为 "user_requirement_error"；
        - 用户要求问题必须说明当前要求不属于道路坡度 DSL 的支持范围。

        如果纯非 slope 请求生成了一个或多个 slope operation，则用户要求不属于本任务范围，同时 DSL 又错误生成了 slope 修改：

        - passed 必须为 false；
        - problem_source 必须为 "both"。

        如果 user_instruction 同时包含 slope 和非 slope 修改：

        - 只检查 slope 部分；
        - 非 slope 部分不应被转换成 slope operation；
        - 不能因为 DSL 没有表达非 slope 修改而判定遗漏；
        - 只要 slope 部分明确、可执行且 DSL 检查通过，非 slope 内容本身不构成 user_requirement_error。
        ==================================================
        # 十一、问题来源判断
        ==================================================

        problem_source 只能使用 "none"、"extraction_error"、"user_requirement_error"、"both"。

        - none：dsl_output 结构正确，字段类型、枚举和组合正确；user_instruction 明确且可执行；DSL 能形成明确完整语义，并与用户要求一致；没有遗漏、增加、重复或冲突 operation。
        - extraction_error：用户要求明确且可执行，但 DSL 提取或转换错误。包括非法 JSON、缺字段、类型或枚举错误、未定义字段、字段组合非法、道路或位置错误、整体抬高/整体坡度误解、grade 与 elevation_delta 混淆、absolute/relative/action/value/unit/方向/程度/传播范围错误、遗漏/增加/重复/冲突 operation、顺序错误、或明确要求下返回空 operations。
        - user_requirement_error：问题只来自用户要求本身，例如无法确定道路或位置、要求矛盾、road_data 上下文冲突、内容不属于 slope、模糊到无法唯一解释；只有当 DSL 对这种无法执行的要求作出正确处理时使用。
        - both：用户要求本身存在问题，同时 DSL 也有独立错误，例如目标道路缺失但 DSL 编造 road_id、无法确定位置但 DSL 自行猜测、非 slope 任务生成 slope operation、用户要求冲突且 DSL 还有结构错误。

        判断优先原则：判断优先原则：DSL 的结构和字段问题属于提取错误；用户要求明确但 DSL 不一致时，应先检查完整动作语义，再检查是否仍满足修改目的；两项均不满足时属于 extraction_error，任意一项满足时不得仅因 mode、action 等字段不同而判定失败。用户要求无法执行且 DSL 正确返回空 operations 属于 user_requirement_error；用户要求无法执行但 DSL 自行猜测属于 both；不能因为 DSL 返回空 operations 就直接判断没有问题。

        ==================================================
        # 十二、输出格式
        ==================================================

        最终只输出一个严格 JSON 对象，固定包含 passed、problem_source、check_result 三个字段，不能增加其他字段。

        {
        "passed": true,
        "problem_source": "none",
        "check_result": "OK"
        }

        - 没有任何结构问题、语义问题或用户要求问题时，passed = true、problem_source = "none"、check_result 固定为 "OK"。
        - 存在任意问题时，passed = false，problem_source 必须为 "extraction_error"、"user_requirement_error" 或 "both"。
        - 如果存在问题，check_result 固定使用："结构问题：具体问题描述；语义问题：具体问题描述；用户要求问题：具体问题描述"。
        - 结构、语义或用户要求没有问题时，对应部分写“无”。
        - dsl_output 无法解析时，结构部分说明具体问题，语义部分写“DSL 无法解析，未进行反向语义检查”。
        - 语义问题必须按顺序说明：当前 DSL 字段组合实际表达什么；用户要求实际表达什么；两者具体有什么区别。
        - 不要输出修改后的完整 DSL、建议 DSL、分析过程、推理步骤、Markdown、代码围栏、换行字符串、数组形式的问题列表或额外字段。

        ==================================================
        # 十三、完整示例
        ==================================================

        ## 一、检查通过示例

        ### 示例 1：正确设置绝对坡度

        #### Input

        ##### user_instruction

        “把当前道路设置为 5% 的上坡。”

        ##### road_data

                {
                    "road_id": "road_21",
                    "start_elevation": 10,
                    "end_elevation": 15,
                    "grade_degree": 2.86
                }

        ##### dsl_output

                {
                    "operations": [
                        {
                            "operation": "slope",
                            "road_id": "road_21",
                            "position": "end",
                            "road_limit": "none",
                            "change": {
                                "attribute": "grade",
                                "mode": "absolute",
                                "action": "set",
                                "magnitude": {
                                    "kind": "numeric",
                                    "value": -5,
                                    "level": "none",
                                    "unit": "percent"
                                }
                            }
                        }
                    ]
                }

        #### 分析过程

        ##### 1. 结构检查

        - dsl_output 是可直接解析的严格 JSON。
        - 顶层仅包含 operations，且 operations 是数组。
        - operation、road_id、position、road_limit、change 和 magnitude 的字段齐全。
        - 字段类型、枚举值及字段组合均合法。
        - grade + absolute + set + numeric + percent 是合法组合。

        ##### 2. 用户要求理解

        - 目标方向：用户没有明确指出道路正方向，使用道路原始坡度方向，从 start 到 end 上坡。
        - 用户未指定受控端。当前 end_elevation 高于 start_elevation，默认使用 position = "end"。
        - 由于坡度方向以 position 指定的端点作为出发点，position = "end" 时，若要表达从 start 到 end 上坡，value 必须为负数。
        - 因为此时调整的position为 end 因此目标值应为 value = -5、unit = percent。

        ##### 3. DSL 反向解释

        当前 DSL 表达：

       “以 road_21 的终点作为受控端和坡度方向出发点，将道路设置为从 end 到 start 下坡 5%；换算到从 start 到 end 的固定道路方向后，即为上坡 5%，且未表达明确的道路传播数量限制。”

        ##### 4. 语义比较与结论

        - 目标道路一致。
        - 修改属性一致。
        - 绝对设置方式一致。
        - DSL 使用 `position = end、value = -5`，实际表示从 `start` 到 `end` 上坡 5%一致，与用户要求一致。
        - 默认受控端和传播范围均可接受。
        - DSL 没有遗漏、增加、重复或冲突操作。

        #### Output

                {
                    "passed": true,
                    "problem_source": "none",
                    "check_result": "OK"
                }
        
        ### 示例 3：正确抬高终点

        #### Input

        ##### user_instruction

        “只把当前道路的终点抬高 4 米，不要影响其他道路。”

        ##### road_data

                {
                    "road_id": "road_8",
                    "start_elevation": 10,
                    "end_elevation": 18,
                    "grade_degree": 4.57
                }

        ##### dsl_output

                {
                    "operations": [
                        {
                            "operation": "slope",
                            "road_id": "road_8",
                            "position": "end",
                            "road_limit": 1,
                            "change": {
                                "attribute": "elevation_delta",
                                "mode": "relative",
                                "action": "increase",
                                "magnitude": {
                                    "kind": "numeric",
                                    "value": 4,
                                    "level": "none",
                                    "unit": "m"
                                }
                            }
                        }
                    ]
                }

        #### 分析过程

                }
            },
            "curvature_peak": {
                "value_type": "curvature | radius | none",
                "change": {
                "mode": "absolute | relative | none",
                "action": "increase | decrease | set | none",
                "magnitude": {
                    "kind": "numeric | qualitative | none",
                    "value": "number | none",
                    "level": "slight | default | significant | none",
                    "unit": "curvature | m | percent | none"
                }
                }
            }
            },
            {
            "centroid_shift": {
                "change": {
                "action": "move_to_start | move_to_end | set | none",
                "mode": "absolute | relative | none",
                "magnitude": {
                    "kind": "numeric | qualitative | none",
                    "value": "number | none",
                    "level": "slight | default | significant | none",
                    "unit": "m | percent | none"
                }
                }
            },
            "curvature_peak": {
                "value_type": "curvature | radius | none",
                "change": {
                "mode": "absolute | relative | none",
                "action": "increase | decrease | set | none",
                "magnitude": {
                    "kind": "numeric | qualitative | none",
                    "value": "number | none",
                    "level": "slight | default | significant | none",
                    "unit": "curvature | m | percent | none"
                }
                }
            }
            }
        ]
        }

        同时检查以下结构要求。

        --------------------------------------------------
        1. operation 基础字段
        --------------------------------------------------

        - operation 必须是字符串 "curve"。
        - road_id 必须是非空字符串。
        - road_limit 必须是大于等于 1 的整数，或者字符串 "none"。
        - shape 必须是对象，并且只能包含 target。
        - shape.target 只能是：
        - "keep"
        - "C-shape"
        - "S-shape"
        - semantic 必须是对象，并且只能包含：
        - semantic_change
        - target
        - semantic.semantic_change 必须是 JSON 布尔值 true 或 false。
        - 不能使用字符串 "true" 或 "false"。
        - semantic.target 只能是：
        - "keep"
        - "left"
        - "right"
        - "left_right"
        - "right_left"

        --------------------------------------------------
        2. modification 结构
        --------------------------------------------------

        - modification 必须是数组。
        - modification 的长度必须严格等于 2。
        - modification[0] 固定表示起点侧、入弯侧或前半段弯道。
        - modification[1] 固定表示终点侧、出弯侧或后半段弯道。
        - 两个 modification 对象都必须字段完整。
        - 每个 modification 必须同时包含：
        - centroid_shift
        - curvature_peak
        - 即使某一侧没有被修改，也不能省略该侧对象。
        - 即使某个子修改没有被使用，也必须输出完整的默认 none 结构。

        不能在最终 DSL 中出现以下内部字段：

        - control_point
        - point_id
        - index
        - p0
        - p1
        - p2
        - p3
        - p_s
        - p_e

        --------------------------------------------------
        3. centroid_shift 格式和内部一致性
        --------------------------------------------------

        centroid_shift.change.action 只能是：

        - "move_to_start"
        - "move_to_end"
        - "set"
        - "none"

        centroid_shift.change.mode 只能是：

        - "absolute"
        - "relative"
        - "none"

        centroid_shift.change.magnitude.kind 只能是：

        - "numeric"
        - "qualitative"
        - "none"

        centroid_shift.change.magnitude.value 只能是：

        - 有限数字
        - 字符串 "none"

        centroid_shift.change.magnitude.level 只能是：

        - "slight"
        - "default"
        - "significant"
        - "none"

        centroid_shift.change.magnitude.unit 只能是：

        - "m"
        - "percent"
        - "none"

        当 centroid_shift.change.action = "none" 时，必须完整满足：

        {
        "action": "none",
        "mode": "none",
        "magnitude": {
            "kind": "none",
            "value": "none",
            "level": "none",
            "unit": "none"
        }
        }

        不能只把 action 设置为 "none"，却保留 relative、numeric、percent 或其他有效修改参数。

        当 centroid_shift 是有效修改时：

        - action 不能是 "none"。
        - mode 不能是 "none"。
        - magnitude.kind 不能是 "none"。
        - kind = "numeric" 时，value 必须是数字，level 必须是 "none"。
        - kind = "qualitative" 时，value 必须是 "none"，level 必须是 slight、default 或 significant。
        - 按米移动通常使用 relative 、numeric 和 m。
        - 按百分比移动通常使用 relative、numeric 和 percent。
        - 没有明确数值的位置调整通常使用 relative、qualitative、对应 level 和 unit = "none"。
        - action = "set" 只有在用户明确给出目标位置时才合理，其他参数必须共同表达该目标位置。

        --------------------------------------------------
        4. curvature_peak 格式和内部一致性
        --------------------------------------------------

        curvature_peak.value_type 只能是：

        - "curvature"
        - "radius"
        - "none"

        curvature_peak.change.mode 只能是：

        - "absolute"
        - "relative"
        - "none"

        curvature_peak.change.action 只能是：

        - "increase"
        - "decrease"
        - "set"
        - "none"

        curvature_peak.change.magnitude.kind 只能是：

        - "numeric"
        - "qualitative"
        - "none"

        curvature_peak.change.magnitude.value 只能是：

        - 有限数字
        - 字符串 "none"

        curvature_peak.change.magnitude.level 只能是：

        - "slight"
        - "default"
        - "significant"
        - "none"

        curvature_peak.change.magnitude.unit 只能是：

        - "curvature"
        - "m"
        - "percent"
        - "none"

        当 curvature_peak.change.action = "none" 时，必须完整满足：

        {
        "value_type": "none",
        "change": {
            "mode": "none",
            "action": "none",
            "magnitude": {
            "kind": "none",
            "value": "none",
            "level": "none",
            "unit": "none"
            }
        }
        }

        不能在 action = "none" 时保留 value_type = "curvature"、mode = "relative" 或其他有效修改参数。

        当 curvature_peak 是有效修改时：

        - value_type 必须是 "curvature" 或 "radius"。
        - mode 不能是 "none"。
        - action 不能是 "none"。
        - magnitude.kind 不能是 "none"。
        - kind = "numeric" 时，value 必须是数字，level 必须是 "none"。
        - kind = "qualitative" 时，value 必须是 "none"，level 必须是 slight、default 或 significant。
        - 相对百分比变化通常使用 relative、numeric 和 percent。
        - 定性变化通常使用 relative、qualitative、对应 level 和 unit = "none"。
        - 绝对曲率数值使用 value_type = "curvature"、mode = "absolute" 和 unit = "curvature"。
        - 绝对半径数值使用 value_type = "radius"、mode = "absolute" 和 unit = "m"。
        - action = "set" 表示设置最终曲率或最终半径，而不是增加量或减少量。

        如果 dsl_output 无法解析为 JSON：

        - 检查不通过。
        - 在检查结果中描述具体的结构问题。
        - 不再进行完整语义检查。

        ==================================================
        二、整体语义检查
        ==================================================

        语义检查不能把每个字段孤立判断。

        你必须先根据 user_instruction 和 road_data 推导用户实际想执行的完整弯道修改，再判断 DSL 中所有参数组合起来是否准确表达了该修改。

        一个完整的 Curve 修改由以下内容共同构成：

        - 修改哪条道路；
        - 是否限制传播到其他道路；
        - 是否修改整体弯道形态；
        - 是否修改道路左右转语义；
        - 修改入弯侧、出弯侧，还是同时修改两侧；
        - 修改的是弯道位置还是弯曲强度；
        - 位置修改是向起点还是向终点；
        - 两个 modification 是同向移动还是反向移动；
        - 弯曲强度使用曲率还是半径表达；
        - 数值表示最终目标值、绝对变化量、百分比变化量还是定性程度；
        - 未被用户要求修改的部分是否正确保持为完整 none 结构。

        只有这些参数组合后的完整含义与 user_instruction 和 road_data 一致，语义检查才算通过。

        --------------------------------------------------
        1. 判断是否为可执行的 Curve 修改
        --------------------------------------------------

        属于 Curve 修改的表达包括但不限于：

        - 把弯道改成 C 型或 S 型；
        - 修改左转、右转、先左后右或先右后左；
        - 入弯更急或更缓；
        - 出弯更鼓或更平顺；
        - 整体弯道提前或推后；
        - 调整前后两个弯之间的距离；
        - 让弯道更对称；
        - 修改弯道曲率或转弯半径。

        以下情况预期应为空 operations：

        - user_instruction 不是弯道修改任务；
        - 无法确定目标道路；
        - 用户只说“调整一下这个弯”，但没有说明形态、语义、位置、弯曲强度、间距或对称性；
        - 用户要求前后冲突，无法形成唯一修改；
        - 用户要求依赖无法获得的信息；
        - 用户直接要求修改 p1、p2、p_s、p_e 等不面向用户的内部参数，且无法转换成明确的自然语言道路修改。

        如果用户要求明确且可执行，但 DSL 返回空 operations，属于提取遗漏。

        如果用户要求无法执行，而 DSL 正确返回空 operations，属于用户要求问题。

        如果用户要求无法执行，但 DSL 自行猜测并生成操作，用户要求和提取过程都存在问题。

        --------------------------------------------------
        2. road_id 和 road_limit
        --------------------------------------------------

        道路判断：

        - 用户明确指定 road_12、12号道路等，目标道路应为 road_12。
        - 用户说“当前道路”“这条路”“选中的道路”，使用 road_data.road_id。
        - 如果用户没有明确指定其他道路，但语境明确指向当前选中道路，可以使用 road_data.road_id。
        - 如果无法确定道路 id，预期应为空 operations。
        - 不能编造 road_id。

        传播范围判断：

        - “只改当前道路”“仅限这条路”“不要影响相邻道路”对应 road_limit = 1。
        - “后面的道路也跟着变”，未指定数量时对应 road_limit = 2。
        - 明确指定最多影响 N 条道路时，对应 road_limit = N。
        - 没有传播范围限制时对应 road_limit = "none"。

        road_id、road_limit 和后续修改必须共同属于同一个用户修改任务。

        --------------------------------------------------
        3. shape 和 semantic 联合检查
        --------------------------------------------------

        shape.target 表达整体弯道形态：

        - 用户没有要求改变形态时，应为 "keep"。
        - “改成 C 型弯”对应 "C-shape"。
        - “改成 S 型弯”对应 "S-shape"。

        semantic 表达道路的转向语义：

        - 用户没有要求修改转向语义时：
        - semantic_change = false
        - target = "keep"
        - 用户明确要求改成左转时：
        - semantic_change = true
        - target = "left"
        - 用户明确要求改成右转时：
        - semantic_change = true
        - target = "right"
        - 用户明确要求先左后右时：
        - semantic_change = true
        - target = "left_right"
        - 用户明确要求先右后左时：
        - semantic_change = true
        - target = "right_left"
        - 用户明确要求保持当前语义不变时：
        - semantic_change = false
        - target = "keep"

        检查 shape 和 semantic 是否共同表达了用户要求。

        例如：

        - 用户只要求“变成 S 型弯”，没有允许或要求语义变化时，不应擅自修改 semantic。
        - 用户只要求改变转向语义，没有要求改变 C/S 形态时，shape.target 应为 "keep"。
        - semantic_change = false 但 target 不是 "keep"，参数组合相互矛盾。
        - semantic_change = true 但 target = "keep"，不能表达明确的语义修改。
        - 用户说“改成 S 型弯，必要时允许语义变化”时，可以结合 road_data.semantic 推导新的 S 型语义。
        - 如果 road_data.semantic = "right"，改成 S 型并允许语义变化时，可以推导为 "right_left"。
        - 如果 road_data.semantic = "left"，改成 S 型并允许语义变化时，可以推导为 "left_right"。

        如果用户只修改 shape 或 semantic，没有表达位置或弯曲强度变化：

        - modification[0] 必须为完整默认 none。
        - modification[1] 必须为完整默认 none。

        --------------------------------------------------
        4. modification[0] 和 modification[1] 的目标映射
        --------------------------------------------------

        modification[0] 固定表示：

        - 起点侧；
        - 入弯侧；
        - 前半段；
        - 前面的弯；
        - 第一个弯；
        - 左边的弯。

        modification[1] 固定表示：

        - 终点侧；
        - 出弯侧；
        - 后半段；
        - 后面的弯；
        - 第二个弯；
        - 右边的弯。

        如果用户明确只修改入弯侧或前半段：

        - 只应修改 modification[0]。
        - modification[1] 应保持完整默认 none，除非用户还提出其他修改。

        如果用户明确只修改出弯侧或后半段：

        - 只应修改 modification[1]。
        - modification[0] 应保持完整默认 none，除非用户还提出其他修改。

        如果用户说：

        - 整体弯道；
        - 整个弯；
        - 整段弯道；
        - 弯道整体；
        - 整体弯曲程度；
        - 没有区分前后两侧的弯曲强度修改；

        通常应同时修改 modification[0] 和 modification[1]。

        必须区分：

        - “左边的弯”表示修改对象是 modification[0]。
        - “往左移动”表示移动方向是起点方向。
        - “右边的弯”表示修改对象是 modification[1]。
        - “往右移动”表示移动方向是终点方向。

        不能因为出现“左”或“右”，就忽略它在句子中表示的是对象位置还是移动方向。

        --------------------------------------------------
        5. 弯曲强度完整语义检查
        --------------------------------------------------

        当用户没有明确说“半径”时：

        - “更急”“更弯”“更鼓”“弯得更明显”默认使用 value_type = "curvature"。
        - 曲率增加表示弯道更急或更鼓。
        - 曲率减小表示弯道更缓或更平顺。

        常见正确组合如下。

        5.1 定性变急或变鼓

        例如：

        - 更急一点；
        - 明显更弯；
        - 更鼓一些。

        通常应表达：

        {
        "value_type": "curvature",
        "change": {
            "mode": "relative",
            "action": "increase",
            "magnitude": {
            "kind": "qualitative",
            "value": "none",
            "level": "slight | default | significant",
            "unit": "none"
            }
        }
        }

        5.2 定性变缓或变平顺

        例如：

        - 更缓一点；
        - 不要那么弯；
        - 明显更平顺。

        通常应表达：

        {
        "value_type": "curvature",
        "change": {
            "mode": "relative",
            "action": "decrease",
            "magnitude": {
            "kind": "qualitative",
            "value": "none",
            "level": "slight | default | significant",
            "unit": "none"
            }
        }
        }

        5.3 曲率半径语义

        如果用户明确使用半径表达：

        - 曲率半径变大，表示弯道变缓。
        - 曲率半径变小，表示弯道变急。

        因此必须检查 value_type、action 和自然语言结果是否一致。

        例如：

        - “曲率半径增加 10 米”应使用 value_type = "radius"、action = "increase"、unit = "m"、value = 10。
        - “曲率半径减小 20%”应使用 value_type = "radius"、action = "decrease"、unit = "percent"、value = 20。
        - 不能因为“弯道变急”，就输出 radius increase。
        - 不能因为“弯道变缓”，就输出 radius decrease。

        5.4 数值含义

        - 设置指定具体值的曲率或半径时，action 应为 "set"。
        - 增加或减少某个数值时，action 应为 "increase" 或 "decrease"。
        - 按百分比变化时，mode 应为 "relative"，unit 应为 "percent"。
        - 绝对曲率数值使用 unit = "curvature"。
        - 绝对半径数值使用 unit = "m"。
        - 20% 的 value 应为 20，而不是 0.2。
        - 定性变化的 value 应为 "none"。
        - numeric 和 qualitative 不能混用。
        - absolute 代表将道路的曲率或者曲率半径调整到某一个具体的值
        - relative 代表在当前道路的曲率或者曲率半径基础上进行修改

        程度词对应关系：

        - 稍微、略微、一点：slight
        - 一些、适当、正常调整：default
        - 明显、大幅、显著：significant

        --------------------------------------------------
        6. 弯道位置和整体平移检查
        --------------------------------------------------

        用户描述弯道位置、出现时机或转弯时机时，通常修改 centroid_shift，而不是 curvature_peak。

        向起点方向移动对应：

        "move_to_start"

        自然语言包括：

        - 往左移动；
        - 往起点方向移动；
        - 提前；
        - 早点转；
        - 弯出现得更早。

        向终点方向移动对应：

        "move_to_end"

        自然语言包括：

        - 往右移动；
        - 往终点方向移动；
        - 推后；
        - 晚点转；
        - 弯出现得更晚。

        整体向起点方向平移时：

        - modification[0].centroid_shift 应为 move_to_start。
        - modification[1].centroid_shift 应为 move_to_start。

        整体向终点方向平移时：

        - modification[0].centroid_shift 应为 move_to_end。
        - modification[1].centroid_shift 应为 move_to_end。

        整体平移的核心特征是两个 modification 同向移动。

        如果用户只表达整体位置移动：

        - 不应自动修改 curvature_peak。
        - shape.target 应为 "keep"，除非用户同时要求改变形态。
        - semantic 应保持不变，除非用户同时要求改变转向语义。

        位置调整的幅度组合应符合自然语言：

        - “移动 5 米”通常对应 relative、numeric、5、m。
        - “移动 20%”通常对应 relative、numeric、20、percent。
        - “提前一点”通常对应 relative、qualitative、slight、none。
        - “推后一些”通常对应 relative、qualitative、default、none。
        - “明显提前”通常对应 relative、qualitative、significant、none。

        --------------------------------------------------
        7. S 型弯间距调整检查
        --------------------------------------------------

        当道路是 S-shape，或者用户明确要求将道路改成 S-shape，并要求调整两个弯之间的距离时，需要检查两个 modification 的反向移动关系。

        增大两个弯之间的间距：

        - modification[0] 向起点方向移动：
        - action = "move_to_start"
        - modification[1] 向终点方向移动：
        - action = "move_to_end"

        减小两个弯之间的间距：

        - modification[0] 向终点方向移动：
        - action = "move_to_end"
        - modification[1] 向起点方向移动：
        - action = "move_to_start"

        间距调整的核心特征是两个 modification 反向移动。

        必须区分：

        - 整体平移：两个 modification 同向移动。
        - 调整间距：两个 modification 反向移动。

        如果用户没有给出具体幅度：

        - mode = "relative"
        - kind = "qualitative"
        - value = "none"
        - level = "default"
        - unit = "none"

        间距调整不应自动修改 curvature_peak。

        如果当前道路不是 S-shape，用户也没有要求改成 S-shape，却要求调整“两个弯之间的间距”，则用户要求本身可能无法执行，应结合完整指令判断为用户要求问题。

        --------------------------------------------------
        8. 对称性联合检查
        --------------------------------------------------

        当用户要求：

        - 对称；
        - 更对称；
        - 匀称；
        - 两边一样；
        - 前后差不多；
        - 入弯和出弯一致；

        需要根据 road_data.p_s 和 road_data.p_e 判断修改方案。

        先计算：

        |p_s - p_e|

        8.1 已经基本对称

        如果：

        |p_s - p_e| < 0.1

        则道路已经基本对称。

        通常应：

        - modification[0].centroid_shift 使用完整默认 none。
        - modification[1].centroid_shift 使用完整默认 none。
        - 如果用户没有表达弯曲强度变化，两个 curvature_peak 也应使用完整默认 none。

        不能因为用户说“更对称”，就在已经基本对称时自动生成明显位置修改。

        8.2 p_s < p_e

        表示左短右长，重心偏左。

        常规修正方案：

        - modification[0] 向终点方向移动；
        - modification[1] 向终点方向移动；
        - 即两个 action 通常均为 "move_to_end"。

        也允许以下单侧修正方案：

        - 只让 modification[1] 向终点方向移动；
        - 当 p_e < 0.5 时，也可以只让 modification[0] 向终点方向移动。

        检查器不能因为 DSL 使用了允许的单侧修正方案，就机械判定为错误。

        8.3 p_s > p_e

        表示左长右短，重心偏右。

        常规修正方案：

        - modification[0] 向起点方向移动；
        - modification[1] 向起点方向移动；
        - 即两个 action 通常均为 "move_to_start"。

        也允许以下单侧修正方案：

        - 只让 modification[0] 向起点方向移动；
        - 当 p_s < 0.5 时，也可以只让 modification[1] 向起点方向移动。

        上述描述都是针对C型曲线的解释，如果是S型曲线就默p_s和p_e的值越接近越对称

        8.4 对称性修正幅度

        对称性修正通常使用：

        - mode = "relative"
        - kind = "qualitative"
        - value = "none"
        - unit = "none"

        level 根据差值判断：

        - 0.10 ≤ |p_s - p_e| < 0.25：slight
        - 0.25 ≤ |p_s - p_e| ≤ 0.40：default
        - |p_s - p_e| > 0.40：significant

        如果用户明确使用“稍微”“明显”等程度词，应同时结合用户程度词和差值判断，但不能输出明显不合理的修改强度。

        如果两个 modification 同时调整：

        - 不应因为两侧同时移动而额外放大 level。
        - 两侧的移动应共同缩小 p_s 和 p_e 的不对称程度。

        对称性修正不应自动修改 curvature_peak，除非用户还明确要求改变弯曲强度。

        --------------------------------------------------
        9. p_s、p_e 和左右方向的内部关系
        --------------------------------------------------

        p_s 和 p_e 只用于检查和计算，不能出现在 DSL 输出中。

        内部方向关系：

        对于 modification[0]：

        - move_to_start 表示向起点移动，p_s 减小。
        - move_to_end 表示向终点移动，p_s 增大。

        对于 modification[1]：

        - move_to_start 表示向起点移动，p_e 增大。
        - move_to_end 表示向终点移动，p_e 减小。

        最终 DSL 使用的是：

        - move_to_start
        - move_to_end

        不能输出 left、right、p_s increase、p_e decrease 等内部描述字段。

        检查时不能只根据 p_s 或 p_e 数值的增减判断 action，还要判断 action 最终表达的是向起点还是向终点移动。

        --------------------------------------------------
        10. 未修改部分的完整 none 检查
        --------------------------------------------------

        用户没有要求的修改不能被自动添加。

        例如：

        - 用户只要求入弯更急，不能自动修改出弯。
        - 用户只要求整体平移，不能自动改变曲率。
        - 用户只要求修改 shape，不能自动修改 centroid_shift 或 curvature_peak。
        - 用户只要求调整间距，不能自动改变 shape、semantic 或 curvature_peak。
        - 用户只要求改变 semantic，不能自动改变 C/S 形态。
        - road_data 中存在 p_s 和 p_e，不代表用户要求修改位置。

        任何未使用的 centroid_shift 或 curvature_peak 都必须是完整默认 none 结构。

        --------------------------------------------------
        11. 多修改和多 operation 检查
        --------------------------------------------------

        如果一句话包含多个独立弯道修改，需要检查 DSL 是否完整表达全部修改。

        例如：

        “第一个弯提前，第二个弯缓一些。”

        应共同表达：

        - modification[0] 的 centroid_shift 向起点移动；
        - modification[1] 的 curvature_peak 减小；
        - 其他未要求部分保持 none。

        不能因为两个修改位于不同侧，就漏掉其中一个。

        如果用户同时要求：

        - 改变 shape；
        - 改变 semantic；
        - 调整位置；
        - 改变弯曲强度；

        这些修改可以共同存在于同一个完整 operation 中。

        比较时应：

        - 忽略 operations 的排列顺序。
        - 检查每条目标道路的全部修改是否完整。
        - 检查是否遗漏用户要求。
        - 检查是否增加用户未要求的修改。
        - 检查不同道路的修改是否被错误合并。
        - 检查是否存在完全重复的 operation。
        - 检查同一道路是否存在互相冲突的修改。
        - 不要因为 modification 固定有两个元素，就把默认 none 对象当成额外修改。

        --------------------------------------------------
        12. 判断参数组合后的实际含义
        --------------------------------------------------

        检查时需要把 DSL 的完整字段组合转换成自然语言含义，再与 user_instruction 比较。

        不要只说某一个字段错误。

        例如：

        - 用户要求“整体弯道提前”，但只有 modification[0] 使用 move_to_start，当前 DSL 实际表达的是只让入弯侧提前，而不是整体平移。
        - 用户要求“增加两个弯之间的间距”，但两个 modification 都使用 move_to_start，当前 DSL 实际表达的是整个弯道向起点平移，而不是两个弯相互远离。
        - 用户要求“第二个弯更缓”，但 DSL 使用 curvature increase，当前 DSL 实际表达的是让第二个弯更急。
        - 用户要求“半径增大”，但 DSL 使用 value_type = "curvature"、action = "increase"，当前 DSL 实际表达的是曲率增大，即弯道变急，与用户要求的变缓相反。
        - 用户只要求改成 S 型弯，但 DSL 同时修改了两个 curvature_peak，当前 DSL 额外改变了用户没有要求的局部弯曲强度。
        - 用户要求入弯更急，但 DSL 修改 modification[1]，当前 DSL 实际修改的是出弯侧。
        - 用户要求弯道更对称，且 p_s < p_e，但 DSL 让两侧向起点移动，当前修改会朝错误方向调整，不符合对称性修正目标。
        - 用户要求整体往终点方向移动 20%，但 DSL 使用 absolute、20 和 m，当前 DSL 实际表达的是向终点移动 20 米，而不是移动 20%。

        语义问题描述必须说明：

        - 用户实际要求什么；
        - 当前 DSL 参数组合表达什么；
        - 两者的具体差异是什么。

        ==================================================
        三、问题来源判断
        ==================================================

        如果检查发现问题，需要进一步判断问题来源。

        problem_source 只能是以下四种值：

        1. "none"

        表示没有发现问题。

        适用情况：

        - dsl_output 结构正确；
        - user_instruction 能够形成明确、可执行的 Curve 修改；
        - DSL 表达的完整修改语义与用户要求及 road_data 一致。

        2. "extraction_error"

        表示 user_instruction 本身明确且可以执行，但 DSL 在提取或转换过程中出现错误。

        包括但不限于：

        - dsl_output 不是合法 JSON；
        - DSL 缺少字段、字段类型错误或使用非法枚举；
        - modification 长度不是 2；
        - 默认 none 结构不完整；
        - 输出了 p_s、p_e、p1、p2 等内部字段；
        - 提取了错误的 road_id；
        - 将入弯侧和出弯侧映射错误；
        - 遗漏了用户要求的 shape、semantic、位置或曲率修改；
        - 增加了用户没有要求的修改；
        - 把整体平移错误提取成单侧移动；
        - 把间距调整错误提取成整体平移；
        - 对称性调整方向或程度错误；
        - 曲率和半径的增减关系错误；
        - mode、action、value_type、value、level、unit 等组合表达了错误含义。

        3. "user_requirement_error"

        表示问题来自 user_instruction 本身，用户要求无法形成明确、唯一、可执行的 Curve 修改。

        包括但不限于：

        - 无法确定目标道路；
        - 用户只说“调整一下这个弯”，没有说明修改内容；
        - 用户要求前后矛盾；
        - 用户要求两个弯之间的间距，但当前和目标形态都无法确定为 S-shape；
        - 用户直接要求操作不可见的内部参数，且无法转换为明确道路语义；
        - 用户要求的内容不属于 Curve 修改；
        - 缺少完成修改所必需的信息。

        如果用户要求存在上述问题，而 DSL 正确返回：

        {
        "operations": []
        }

        则不属于提取错误，但整体检查仍不通过，problem_source 应为 "user_requirement_error"。

        4. "both"

        表示用户要求本身存在问题，同时 DSL 也存在独立的提取错误。

        例如：

        - 用户没有提供可确定的道路，但 DSL 编造了 road_id；
        - 用户只说“调整一下这个弯”，但 DSL 自行猜测为曲率增加；
        - 当前道路不是 S-shape，用户也没有要求改成 S-shape，却要求调整两个弯的间距，DSL 仍自行生成反向移动；
        - 用户直接要求修改 p_s，DSL 又把 p_s 输出成未定义字段；
        - 用户要求无法执行，并且 dsl_output 本身还存在 JSON 或字段结构问题。

        判断要求：

        - DSL 的结构问题都属于提取过程中的错误。
        - 用户要求明确，但 DSL 与用户要求不一致时，属于 "extraction_error"。
        - 用户要求无法明确执行，并且 DSL 正确返回空 operations 时，属于 "user_requirement_error"。
        - 用户要求无法明确执行，但 DSL 仍然猜测或生成错误操作时，属于 "both"。
        - 用户要求本身存在问题，同时 DSL 还有独立结构错误时，属于 "both"。
        - 不能因为 DSL 返回空 operations，就直接判断没有问题，必须先判断用户要求是否明确且可执行。

        ==================================================
        四、输出格式
        ==================================================

        最终只输出一个 JSON 对象，固定包含以下三个字段：

        {
        "passed": true,
        "problem_source": "none",
        "check_result": "OK"
        }

        字段说明：

        1. passed

        - 没有任何结构问题、语义问题或用户要求问题时输出 true。
        - 存在任意问题时输出 false。
        - passed 为 true 时，problem_source 必须为 "none"。
        - passed 为 false 时，problem_source 不能为 "none"。

        2. problem_source

        只能使用：

        - "none"
        - "extraction_error"
        - "user_requirement_error"
        - "both"

        3. check_result

        如果没有问题，固定输出：

        "OK"

        如果存在问题，使用一个字符串描述结构问题、语义问题和用户要求问题，格式为：

        "结构问题：具体问题描述；语义问题：具体问题描述；用户要求问题：具体问题描述"

        要求：

        - 如果结构没有问题，输出“结构问题：无”。
        - 如果语义没有问题，输出“语义问题：无”。
        - 如果用户要求没有问题，输出“用户要求问题：无”。
        - 如果 DSL 无法解析，说明具体结构问题，并输出“语义问题：DSL 无法解析，未进行语义检查”。
        - 如果有多个问题，应在对应部分中依次说明。
        - 问题描述应说明当前 DSL 完整参数组合实际表达了什么，以及与用户要求有什么差异。
        - 不要只写“字段错误”“参数错误”“方向错误”或“语义不一致”等笼统结论。
        - 不要输出修改后的完整 DSL。
        - 不要输出分析过程。
        - 不要增加其他字段。

        通过示例：

        {
        "passed": true,
        "problem_source": "none",
        "check_result": "OK"
        }

        提取错误示例：

        {
        "passed": false,
        "problem_source": "extraction_error",
        "check_result": "结构问题：无；语义问题：用户要求将整体弯道往终点方向移动 20%，但当前 DSL 只修改 modification[0]，并使用 absolute、20 和 m，实际表达的是仅将入弯侧向终点移动 20 米，没有移动出弯侧，也没有表达百分比调整；用户要求问题：无"
        }

        用户要求问题示例：

        {
        "passed": false,
        "problem_source": "user_requirement_error",
        "check_result": "结构问题：无；语义问题：DSL 返回空 operations，符合无法确定具体修改内容时不生成操作的规则；用户要求问题：用户只要求调整一下弯道，没有说明修改形态、语义、位置、弯曲强度、间距或对称性，无法形成明确的 Curve 修改"
        }

        两者都有问题的示例：

        {
        "passed": false,
        "problem_source": "both",
        "check_result": "结构问题：modification 数组只有一个元素，缺少固定对应出弯侧的 modification[1]；语义问题：用户没有说明希望弯道更急、更缓、提前、推后或改变形态，但当前 DSL 自行生成了入弯侧曲率增加；用户要求问题：用户只说调整一下当前弯道，缺少明确的修改目标"
        }

        JSON 无法解析的示例：

        {
        "passed": false,
        "problem_source": "extraction_error",
        "check_result": "结构问题：dsl_output 不是合法 JSON，存在尾随逗号；语义问题：DSL 无法解析，未进行语义检查；用户要求问题：无"
        }

# Slope DSL 规范

    本规范只定义 Slope DSL 的数据结构、字段语义、规范化规则和合法性约束。提取任务和检查任务必须共同遵守本规范。

    ## 1. 支持范围

    Slope DSL 只表达以下道路修改：

    - 道路坡度百分比；
    - 道路坡角；
    - 道路变陡或变缓；
    - 起点或终点的绝对高程；
    - 起点或终点的相对升降；
    - 起点和终点的等量整体升降；
    - 道路修改的传播数量限制。

    道路宽度、车道数量、弯道、曲率、转弯半径、材质和颜色不属于 Slope DSL。

    当用户请求不包含任何 Slope DSL 支持范围内的修改时，规范 DSL 为：

    {
    "operations": []
    }

    ## 2. 顶层结构

    {
    "operations": [
    {
        "operation": "slope",
            "road_id": "string",
            "position": "start | end | both",
            "road_limit": "number | none",
            "change": {
                "attribute": "grade | elevation_delta | none",
                "mode": "absolute | relative | none",
                "action": "increase | decrease | set | none",
                "magnitude": {
                    "kind": "numeric | qualitative | none",
                    "value": "number | none",
                    "level": "slight | default | significant | none",
                    "unit": "percent | degree | m | none"
                }
            }
        }
    ]
    }


    没有有效修改时使用空 operations。

    ## 3. road_id

    road_id 是每个 operation 的必填字段。

    road_id 的来源优先级为：

    1. user_instruction 明确指定的道路 ID；
    2. user_instruction 中的“当前道路”“这条路”“选中的道路”等表达，对应 road_data.road_id。

    用户明确指定的道路 ID 优先于 road_data.road_id。

    如果无法确定 road_id，不得编造，规范 DSL 为：

    {
    "operations": []
    }

    ## 4. position 的唯一语义

    position 表示实际被修改或受控的道路端点：

    - start：修改或控制起点；
    - end：修改或控制终点；
    - both：同时对起点和终点执行相同的水平高度修改。

    position 不同时承担其他含义。坡度方向需要结合 position 和 value 共同解释。

    ### 4.1 grade 的 position

    grade 类型的修改不允许使用 position = both。

    用户明确指定受控端点时：

    - 起点、起始端、入口端：start；
    - 终点、结束端、出口端：end。

    
    用户未指定受控端点时：
    - end_elevation > start_elevation：end；
    - start_elevation > end_elevation：start；
    - start_elevation = end_elevation：end。


    ### 4.2 elevation_delta 的 position

    - 明确修改起点：start；
    - 明确修改终点：end；
    - 明确整条道路、全段、起终点同时等量升降：both；

    ## 5. road_limit

    road_limit 表示最多允许受到该 operation 影响的道路数量，包含初始目标道路。

    - 只改当前道路、不要影响相邻道路：1；
    - 相邻道路或后续道路跟随修改，但未指定数量：2；
    - 最多影响 N 条道路：正整数 N；
    - 用户没有表达传播范围默认为："none"。

    road_limit 只能是大于等于 1 的整数或字符串 "none"。

    ## 6. change.attribute

    - 坡度、坡角、上坡、下坡、变陡、变缓：grade；
    - 起点高程、终点高程、端点抬高或降低、整条道路整体升降：elevation_delta。

    只有“调整一下”“优化一下”等无法判断具体修改属性的请求，不得默认解释为 grade，规范 DSL 为空 operations。

    ## 7. change.mode 和 change.action

    ### 7.1 absolute + set

    表示将目标属性设置为一个不依赖当前值的绝对目标：

    - 坡度设为 5%；
    - 坡角设为 3 度；
    - 终点高程设为 10 米。

    ### 7.2 relative + increase/decrease

    表示在当前值基础上进行增减：

    - 坡度增加 20%；
    - 坡度减少 30%；
    - 坡角增加 3 度；
    - 终点抬高 4 米；
    - 起点降低 2 米。

    increase 和 decrease 的 numeric value 必须大于 0。增减方向由 action 表达，不使用负 value 表达增加或减少。

    ### 7.3 relative + set

    表示将最终值设置为当前值的指定比例：
    - 坡度调到当前的 30%。
    - 高度调整到当前的 20%

    该组合只允许 unit = percent，value 表示最终值占当前值的百分比。

    “坡度/高度 调到当前的一半”对应 value = 50。

    用户表示将“某点高度设置为当前的百分之X”时，使用relative + set + percent

    relative + set + degree/m 为非法组合。

    ## 8. magnitude

    ### 8.1 numeric

    用户提供明确数值，或规范明确允许根据完整输入唯一计算出数值时：

    - kind = numeric；
    - value 为有限数字；
    - level = "none"；
    - unit 为 percent、degree 或 m。

    不得假设道路长度或其他未提供的数据进行计算。

    ### 8.2 qualitative

    用户表达明确修改方向和程度，但没有数值时：

    - kind = qualitative；
    - value = "none"；
    - unit = "none"。

    程度映射：

    - 稍微、略微、一点、小幅：slight；
    - 一些、适当、正常程度，或仅表达变陡/变缓但未给程度：default；
    - 大幅、明显、显著、很多：significant。

    仅有“调整”“修改”等表达，既没有方向也没有程度时，不构成 qualitative 修改。

    ## 9. 单位

    ### grade

    - 坡度默认为 degree 角度
    - 百分比、%、百分比坡度：percent；
    - 坡度、角度、度：degree。

    ### elevation_delta

    - 表示高度修改
    - 绝对高程或高程变化量使用单位：m。
    - elevation_delta + relative + set + percent 表示：最终端点绝对高程 = 当前端点绝对高程 × value / 100

    用户只表达“抬高”“降低”但没有数字时，可以使用 qualitative，此时 unit = "none"。


    ## 10. grade 的坡度方向规则

    ### 10.1 基本概念

    grade 修改中需要区分：

    * **坡度描述方向**：用户从哪个端点朝另一端描述坡度；
    * **position**：实际发生高程变化的受控端点。

    两者可能相同，也可能不同。

    坡度描述方向不写入 DSL。提取时先确定用户要求的物理坡向，再换算为相对于 position 的 DSL value。

    grade 不允许使用 position = both。

    ### 10.2 坡度正负号

    从端点 A 朝端点 B 观察：

    * value > 0：A → B 上坡；
    * value < 0：A → B 下坡；
    * value = 0：平路。

    同一条道路从相反端点观察时，数值符号相反。

    例如：

    * start → end 上坡 5 度；
    * 等价于 end → start 下坡 5 度。

    ### 10.3 原始道路方向

    根据端点高程判断：

    * end_elevation > start_elevation：

    * 原坡向为 start → end 上坡；
    * 当前高端为 end。

    * start_elevation > end_elevation：

    * 原坡向为 end → start 上坡；
    * 当前高端为 start。

    * start_elevation = end_elevation：

    * 原道路为平路；
    * 默认描述方向为 start → end；
    * 默认 position = end。

    ### 10.4 默认描述方向和 position

    用户没有明确指定描述方向或受控端点时：

    * 原道路有坡度：

    * 默认描述方向沿原道路上坡方向；
    * position 取当前高端。

    * 原道路为平路：

    * 默认描述方向为 start → end；
    * position = end。

    用户明确说“起点的坡度”时：

    * 描述方向为 start → end；
    * position = start。

    用户明确说“终点的坡度”时：

    * 描述方向为 end → start；
    * position = end。

    用户只说“从起点到终点上坡/下坡”时，只明确了物理坡向；若没有明确受控端点，position 仍按默认规则确定。

    ### 10.5 DSL value 换算

    最终 DSL value 必须相对于 position 解释：

    * position = start：

    * DSL value 等于 start → end 的有符号坡度。

    * position = end：

    * DSL value 等于 start → end 有符号坡度的相反数。

    例如目标为 start → end 上坡 5 度：

    * position = start：value = 5；
    * position = end：value = -5。

    目标为 start → end 下坡 5 度：

    * position = start：value = -5；
    * position = end：value = 5。

    不得直接复制用户原文中的正负号，必须先确定描述方向和物理坡向，再换算成相对于 position 的 value。

    ### 10.6 绝对设置

    对于：

    * attribute = grade；
    * mode = absolute；
    * action = set；
    * kind = numeric。

    用户未明确坡向时：

    * 原道路有坡度：保持原坡向；
    * 原道路为平路：默认形成 start → end 上坡。

    用户提供带正负号的数值时，正负号相对于当前采用的描述方向解释，然后再换算为 DSL value。

    ### 10.7 相对增加和减少

    grade 的 increase/decrease 修改的是坡度或坡角的绝对大小，不是直接对有符号坡度做加减。

    * increase：变陡，增加坡度绝对值；
    * decrease：变缓，减小坡度绝对值；
    * 默认保持原坡向；
    * decrease 最多减小到平路，不允许越过 0 后反转坡向；
    * numeric value 必须大于 0。

    例如原坡角为 3 度，用户要求降低 5 度，最终为平路，不得反向变成 2 度坡。

    ### 10.8 平路特殊规则

    平路默认：

    * 描述方向为 start → end；
    * position = end。

    用户明确数值增加：

    * “坡度增加 5 度”表示形成 start → end 上坡 5 度。

    用户明确数值降低：

    * “坡度降低 5 度”是特殊情况，表示形成 start → end 下坡 5 度。

    百分比相对增加或降低仍按用户表达正常提取，实际结果由执行代码处理。

    平路上的定性变缓没有实际效果，规范 DSL 为：

    {
    "operations": []
    }

    平路上的定性变陡是有效操作，默认形成 start → end 上坡。

    ### 10.9 相对比例设置

    grade + relative + set + percent 表示：

    最终坡度大小 = 当前坡度大小 × value / 100。

    规则：

    * 默认保持原坡向；
    * value = 0：变为平路；
    * value = 50：变为当前的一半；
    * value = 100：保持不变；
    * value > 100：变得更陡；
    * value 不得为负；
    * 不允许通过负值反转坡向。

    ### 10.10 解析顺序

    所有 grade 修改按以下顺序处理：

    1. 判断原道路坡向或是否为平路；
    2. 确定用户的坡度描述方向；
    3. 确定实际受控端点 position；
    4. 判断 absolute、increase、decrease 或 relative set；
    5. 确定目标物理坡向和坡度大小；
    6. 将目标坡度换算为相对于 position 的 DSL value。

    ## 11. grade 的相对修改语义

    grade 的 relative increase/decrease 操作作用于当前坡度或坡角的大小，坡度越大道路越陡峭。
    默认保持当前物理坡向，不直接对有符号 value 做加减。

    ### relative + increase/decrease + percent

    - increase + X percent：
    最终坡度大小 = 当前坡度大小 × (1 + X / 100)；
    - decrease + X percent：
    最终坡度大小 = 当前坡度大小 × (1 - X / 100)；
    - decrease 的 value 必须满足 0 < value <= 100；
    - 操作默认保持当前坡向；
    - 当前道路为平路时，按比例增加仍然得到 0，不会自行产生坡向。

    ### relative + increase/decrease + degree

    - increase + X degree：
    最终坡角大小 = 当前坡角大小 + X；
    - decrease + X degree：
    最终坡角大小 = 当前坡角大小 - X；
    - 默认保持当前坡向；
    - 最终坡角大小不得小于 0，也必须小于 90 度。

    ## 12. elevation_delta 的语义

    ### relative + increase/decrease + m

    表示对 position 指定端点进行高程增减：

    - start：只修改起点；
    - end：只修改终点；
    - both：起点和终点等量修改。

    ### both 表示对起点和终点应用同一组 change 参数。

    不同字段组合下：

    - relative + increase/decrease + m：
    两个端点发生相同米数的高程变化；
    - absolute + set + m：
    两个端点被设置为相同的最终绝对高程；
    - relative + set + percent：
    两个端点分别以各自当前高程为基准应用相同比例，


    ### absolute + set + m

    表示将 position 指定端点的最终绝对高程设置为 value 米。

    - position = start：设置起点最终高程；
    - position = end：设置终点最终高程；
    - position = both：将两个端点都设置为同一个绝对高程。

    ### grade + relative + set + percent：

    - 最终坡度大小 = 当前坡度大小 × value / 100；
    - 默认保持当前坡向；
    - value = 0 时最终为平路；
    - value > 100 表示最终坡度比当前坡度更陡；
    - 当前道路为平路时，正常提取DSL；
    - 不允许通过负 value 表达坡向反转。

    ## 13. 多 operation 规范化

    以下情况必须拆成多个 operation：

    - 不同道路；
    - 不同 attribute；
    - 不同位置且动作、模式、数值、单位或程度不同；
    - 多个按照顺序分别执行的独立修改。

    起点和终点执行完全相同的 elevation_delta 修改时，规范化为一个 position = both 的 operation。

    多个 operation 按用户表达顺序排列。

    非 Slope 修改不得生成 slope operation。请求同时包含 Slope 和非 Slope 修改时，只表达 Slope 部分。

    ## 14. 空 operations

    以下情况规范 DSL 为：

    {
    "operations": []
    }

    - 不属于 Slope DSL 支持范围；
    - 无法确定 road_id；
    - 无法确定必要的 position；
    - 无法确定 attribute；
    - 用户要求内部冲突；
    - 缺少形成唯一操作所必需的信息；
    - 用户要求过于模糊，无法确定实际修改动作。

    ## 15. 数据一致性

    road_data 中：

    - start_elevation 和 end_elevation 是端点高程的权威来源；
    - grade_degree 使用 start 到 end 固定方向；
    - grade_degree > 0 表示 start 到 end 上坡；
    - grade_degree < 0 表示 start 到 end 下坡；
    - grade_degree = 0 表示平路。

    如果 grade_degree 与端点高程所表达的坡向明显冲突，不得自行修正数据，规范 DSL 为空 operations。

    ## 16. 一致性约束

    - 所有 operation 字段必须完整；
    - JSON 中不得使用 null；
    - 不得包含规范中未定义的字段；
    - grade 不允许 position = both；
    - numeric value 必须是有限数字；
    - increase/decrease 的 numeric value 必须大于 0；
    - grade + absolute + set + degree 必须满足 -90 < value < 90；
    - relative + set 只允许 unit = percent，且 value 必须大于等于 0；
    - elevation_delta + absolute + set 只允许 unit = m；
    - qualitative magnitude 的 value 和 unit 必须为 "none"；
    - numeric magnitude 的 level 必须为 "none"。

    ## 17.合法字段组合
    只有以下组合合法，未列出的组合全部非法。
    ### grade

    1. absolute + set + numeric + percent
    2. absolute + set + numeric + degree
    3. relative + increase + numeric + percent
    4. relative + decrease + numeric + percent
    5. relative + increase + numeric + degree
    6. relative + decrease + numeric + degree
    7. relative + set + numeric + percent
    8. relative + increase + qualitative + none
    9. relative + decrease + qualitative + none

    ### elevation_delta

    1. absolute + set + numeric + m
    2. relative + increase + numeric + m
    3. relative + decrease + numeric + m
    4. relative + increase + qualitative + none
    5. relative + decrease + qualitative + none
    6. relative + set + numeric + percent
    仅当业务明确支持“设置为当前绝对高程的某个比例”时合法。

    ## 18. 规则优先级

    规则优先级由高到低：

    1. 用户明确指定的道路、受控端点、方向、动作和数值；
    2. 字段合法性与组合约束；
    3. attribute 专属规则；
    4. position 默认规则；
    5. 坡向默认规则；
    6. 其他默认规则；
    7. 示例。

    示例与正文冲突时，以正文为准。通用规则与 attribute 专属规则冲突时，以 attribute 专属规则为准。
